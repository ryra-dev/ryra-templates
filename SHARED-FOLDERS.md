# Shared folders

One machine can host several named spaces. Each person keeps their own account,
home, agent sessions and credentials, with shortcuts to shared content:

```text
/home/alice/Shared/Company  -> /srv/shared/company
/home/alice/Shared/Research -> /srv/shared/research
/home/bob/Shared/Company    -> /srv/shared/company
```

Enable spaces in the machine's `configuration.nix` or a local module:

```nix
{ ... }: {
  ryra.sharedFolders = {
    company = {
      label = "Company";
      members = [ "alice" "bob" ];
    };
    research = {
      label = "Research";
      members = [ "alice" "deploy" ];
      path = "/data/research";
    };
  };
}
```

Members are Linux accounts: personal logins such as those generated by Ryra's
login module, shared logins, or accounts made by hand on the machine. Accounts
this configuration declares as normal users with a home get a shortcut; others
get the group and reach the space by its path. An account may be listed before
it is made by hand, and has access once it exists. This option does not create
accounts or grant SSH, sudo, access to an agent session, or credentials. Ryra
writes this option from `[[shared_folders]]` in `organization.toml`; manage
those with `ryra machine folders` or a machine's Shared folders settings.

The attribute name is a stable storage identifier: `company` means
`/srv/shared/company` and Unix group `ryra-shared-company`. Use up to 20 lowercase
letters, digits or hyphens, starting with a letter. `label` is the shortcut's
friendly name and defaults to the identifier. Labels must be unique. Choose
meaningful names such as `company`, `research` or `client-acme`, rather than
numbered copies of `shared`. Nothing is enabled by default.

`path` stores a space somewhere other than `/srv/shared/NAME`, such as a data
volume. It is an absolute path of at least two parts made of letters, digits,
dots, underscores or hyphens, outside the system's own directories and `/home`,
and spaces may not share or nest their paths. Missing parent directories are
created by root with mode `0755`.

Directories are root-owned, setgid and accessible to their group (`2770`).
Default POSIX ACLs let normally created files and subdirectories inherit group
write access, including when a member's usual umask is restrictive. Each space
has its own group, and its membership is exactly the list: activation removes
anybody else, including members NixOS would otherwise keep because they were
added by hand. `/srv/shared` allows traversal without listing all spaces. Root
and machine administrators can access the content.

Shortcuts are created on boot and configuration activation, after the storage
and home mounts are available. Existing files, directories and different
symlinks at a shortcut's location are preserved. If a name is already occupied,
choose another label or move that item yourself. Keep `~/Shared` as a directory;
the module does not replace it with a link to everybody's spaces.

Changing an identifier or a path creates a new storage location; it does not move
data. Activation tidies up after a change and never deletes a file: a former
location is removed when it is empty and otherwise stays where it is, with the
shortcuts that point at it, and a shortcut under an old label, to a space the
account was taken out of, or to a former location that is gone, is removed by
that account. Former locations are remembered in
/var/lib/ryra-shared-folders/paths. Access comes from the
target directory's ACL and group, not the presence of a shortcut.

A process keeps the groups it started with, and a lingering login, its herdr
session and every pane in it can run for weeks. So every member with an account
is also named in the ACL of the space and of everything already in it, with
default entries on its directories for what is made later: a session that
started before they were added opens it at once, and joining never restarts
anybody's session. The ryra-shared-folders service does this when membership
changes, after tmpfiles and the mounts, remembering by uid what it granted in
/var/lib/ryra-shared-folders/named; it walks the space with systemd-tmpfiles,
which does not follow a link a member swaps in. A member who leaves loses the
entry on the space itself, which is all that lets anybody past it, and an
account named before it exists is covered the next time membership changes;
its first login has the group anyway. A running session keeps a group it lost,
so withdrawing access from one requires ending that session; removing a member
does not erase copies they already have.

Existing contents are not recursively repaired. Files moved from elsewhere,
copies that preserve permissions, programs requesting mode `0600`, and later
`chmod` calls can restrict collaboration. Filesystem permissions do not merge
concurrent writes or provide revision history. Validate the actual editors and
agents used by the team. Members can rename or delete entries in shared writable
directories.

Back up `/srv/shared` and any other space paths separately, with versioning and a tested restore. Home
backups that do not follow symlinks will not include it. The templates' existing
`/home` and `/var/lib` deployment snapshots do not cover these documents. No disk
layout or persistent mount is changed by enabling this module; configure storage
explicitly if the machine uses an ephemeral root or a separate data volume.

Validation:

```sh
python3 tests/check_shared_folders.py
# Apple Silicon macOS with Lima; creates and deletes its own isolated test VM.
python3 tests/check_shared_folders_vm.py
```

The Linux test uses distinct accounts to check actual shared writes, denied
access, permission inheritance, existing shortcut collisions and membership
removal. It exercises the evaluated tmpfiles rules without deploying a machine
configuration or changing existing VMs.

Ryra Files collaborates directly on accessible text files. These templates
provision folders and permissions; they are not required for live editing.
